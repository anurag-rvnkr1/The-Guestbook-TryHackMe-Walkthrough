# Security Policy

> **The Guestbook — TryHackMe Walkthrough**
>
> Security Policy for the public GitHub repository documenting the TryHackMe **The Guestbook** room.
>
> This repository contains **educational cybersecurity documentation only**. It does **not** contain exploit tooling, sensitive credentials, or the final challenge flag.

---

## Supported Versions

This repository is a documentation project rather than production software. Security updates primarily apply to documentation quality, accidental disclosure, and repository configuration.

| Version                              | Supported |
| ------------------------------------ | --------- |
| Latest `main` branch                 | ✅ Yes     |
| GitHub Pages documentation (`docs/`) | ✅ Yes     |
| Previous commits/releases            | ❌ No      |

Always use the latest version of the repository for documentation and GitHub Pages.

---

## Repository Scope

This repository includes:

* Professional TryHackMe walkthrough documentation.
* GitHub Pages portfolio site.
* Security analysis of the challenge.
* Blue Team recommendations.
* AI Security concepts and threat modeling.
* Educational screenshots captured from the authorized lab.

This repository **does not** include:

* Challenge flags.
* Private credentials.
* Authentication tokens.
* Production secrets.
* Exploit automation against real systems.

---

## Responsible Use

The techniques discussed in this repository are demonstrated **only** within an authorized TryHackMe laboratory environment.

### Authorized Uses

* Cybersecurity education.
* CTF practice.
* AI security research.
* Web application security learning.
* Portfolio demonstration.
* Defensive security awareness.

### Unauthorized Uses

Do **not** use the documented techniques against:

* Production infrastructure.
* Third-party web applications.
* Systems you do not own.
* Services without explicit written authorization.

Unauthorized testing may violate laws, platform policies, or terms of service.

---

## Sensitive Content Policy

To preserve the educational value of the room and respect TryHackMe's platform guidelines, this repository intentionally redacts sensitive challenge content.

### Publicly Redacted

* 🚩 Final challenge flag.
* Manager-only secrets.
* Sensitive encoded outputs.
* Spoiler-heavy responses.
* Internal protected resource values.

### Included

* Methodology.
* Attack chain.
* Security concepts.
* Threat modeling.
* Defensive recommendations.
* Educational screenshots.

This repository is intended to teach **how the vulnerability works**, not to publish direct answers.

---

## Reporting a Security Issue

If you discover a security-related issue in this repository (such as accidental disclosure of sensitive information or exposed secrets), please report it responsibly.

### Please Report

* Accidental publication of challenge flags.
* Embedded credentials or API keys.
* Sensitive personal information.
* Broken GitHub Pages configuration exposing secrets.
* Documentation issues that unintentionally reveal protected challenge answers.

### Please Do Not Report

* Expected CTF behavior.
* Educational screenshots from the TryHackMe lab.
* Redacted challenge content.
* Intended walkthrough methodology.

---

## Disclosure Guidelines

When reporting an issue, include:

* Repository section or file affected.
* Description of the issue.
* Steps to reproduce (if applicable).
* Suggested remediation (optional).

Avoid posting sensitive information publicly inside GitHub Issues.

## Secure AI Development Recommendations

The documentation recommends several defensive controls for AI-powered applications.

### Recommended Controls

* Prompt isolation.
* Server-side authorization.
* Tool allowlisting.
* Least privilege for AI agents.
* Audit logging for AI tool execution.
* Policy enforcement outside the language model.

These recommendations are intended for developers building secure AI applications.

## GitHub Pages Security

The GitHub Pages site is designed to be a **static documentation website**.

### Security Practices

* No server-side code.
* No authentication.
* No API secrets.
* No client-side credentials.
* Static assets only.
* Relative links only.

This minimizes the attack surface of the documentation site.
